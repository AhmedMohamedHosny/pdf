DOCUMENTATION & TRANSPARENCY

Help, Supported Formats & Technical Limitations

Clear, honest documentation of how AhmedPdf processes files, supported formats, and technical constraints.

Supported Format Matrix

  • PDF Tools: Merge, Split, Extract, Rotate, Reorder, Delete Pages, Watermark, Page Numbers, Header/Footer, Signature Image Overlay, Metadata Edit, PDF to JPG/PNG/WEBP, PDF to TXT, PDF to DOCX.
  • Word (.docx): DOCX to PDF, DOCX to HTML, DOCX to TXT, TXT to DOCX (real OpenXML package), Live Document Preview.
  • Excel & Spreadsheets (.xlsx, .xls, .csv): XLSX to CSV, CSV to XLSX, XLSX to PDF, XLSX to HTML/JSON with multi-sheet selection.
  • PowerPoint (.pptx): Slide text & structure extraction (`ppt/slides/slide*.xml`) to PDF and TXT preview.
  • Images (JPG, PNG, WEBP, GIF, BMP, SVG): Cross-conversion, quality compression, exact pixel resize, rotation, aspect-ratio crop, and batch Images to PDF.
  • Archives (.zip): Create ZIP from files/folders, inspect & extract ZIP with path-traversal and zip-bomb guards.

Known Technical Limitations (Transparency)

  • PDF to DOCX Layout: Extracts text paragraphs into a valid `.docx` file; complex multi-column floating tables or vector graphics may not preserve exact visual positioning.
  • Scanned PDFs & OCR: Image-only scanned PDFs do not contain embedded text streams. Use the built-in OCR Vision Tool (Tesseract.js) to extract text from scanned pages.
  • Office to PDF Formatting: In-browser DOCX/XLSX/PPTX to PDF renders structured document content and tables cleanly, while full native Microsoft fonts/macros require a headless LibreOffice backend worker.
  • PDF Encryption: Password verification and decrypting user-authorized PDFs are supported; removing unknown passwords without authorization is never performed.
SECURITY ARCHITECTURE

Privacy Policy & Security Controls

How AhmedPdf protects your documents and enforces strict validation.

1. Local-First Execution

All core PDF manipulations, image conversions, Office document parsing, and ZIP operations execute locally inside your browser's memory and sandboxed IndexedDB. Your sensitive documents are never silently uploaded to third-party servers.

2. Magic-Byte File Signature Verification

AhmedPdf never trusts file extensions alone. Before processing, the engine inspects binary magic headers (%PDF-, PK\x03\x04, \xFF\xD8\xFF, \x89PNG, RIFF..WEBP) to reject spoofed or corrupted files.

3. Archive Extraction Safety (Zip-Slip & Bomb Guard)

When browsing or extracting ZIP archives, AhmedPdf sanitizes all entry paths to block ../ path traversal, restricts maximum entry counts, and checks uncompressed size ratios before allocating memory.
